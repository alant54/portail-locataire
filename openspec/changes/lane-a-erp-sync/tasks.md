- [x] 2.1b **Read `tenant-account-entries` and `rent-terms` per lease, never by `offset`.** Offset paging is lossy on exactly these two (161 603 fetched / 133 455 distinct; 4 725 / 4 724) and two walks disagree, which produced a 3 750 CHF balance for BAIL-000170 against an oracle of 2 540. Verify the four fixture tenants' computed balances equal `fixtures/meta.json` exactly, and that the other 13 collections stay on offset paging
- [x] 2.2 **Seed the cursor from the full import.** Read `max(change_id)` from `sync-events` **before** the first collection is fetched, then write it into `sync_cursor` in the transaction that finishes the import (reading it first replays rather than skips anything that lands mid-import). Without this the cursor stays at 0 and the first `npm run sync` replays all 20 665 events — a 7–10 minute no-op that hangs lane C's "Relancer la synchro". Verify `sync_cursor.last_change_id` equals the ERP's max (20 665 today) right after `npm run sync:full`, and that an immediately following `npm run sync` applies **0** events
- [x] 2.3 Verify idempotency: run `npm run sync:full` twice and assert identical `SELECT count(*)` per table (add this as `scripts/check-idempotent.sh`).
